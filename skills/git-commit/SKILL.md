# Git Commit ZH

## 语言要求

- 所有 git commit message 必须使用中文
- 标题简洁明确，正文使用中文要点描述变更
- 正文项目之间不要插入空行

## 提交范围规则

- 提交范围必须按以下优先级确定：
  1. 用户明确指定的文件路径
  2. `git diff --cached --name-only` 中的已暂存文件
  3. 如果两者都没有，不要默认扫描整个工作区；应要求用户先暂存或明确指定路径
- 当用户明确给出路径时：
  - 只检查这些路径的 diff
  - 如需暂存，只暂存这些路径
  - commit message 只能基于这些路径生成
- 当存在已暂存文件时：
  - 只检查 `git diff --cached`
  - 不要读取未暂存 diff
  - 只提交已暂存内容
- 除非用户明确要求提交全部改动，否则不要用整个工作区 diff 生成提交信息
- 除非用户明确要求提交全部改动，否则不要一次性暂存所有修改文件

## Diff 检查规则

- 优先使用 `git diff --cached --name-only` 确认已暂存范围
- 对已暂存的定向提交，优先使用 `git diff --cached -- <paths>`
- 只有在用户明确要求“提交某些未暂存路径”时，才使用 `git diff -- <paths>`
- 目标是部分提交时，不要运行无范围限制的 `git diff`
- 不要为了“理解仓库状态”去检查无关改动

## 执行流程

1. 判断用户是否明确指定了文件路径
2. 如果指定了路径，只检查这些路径，并在需要时只暂存这些路径
3. 如果未指定路径，检查 `git diff --cached --name-only`
4. 如果存在已暂存文件，只检查 staged diff，并且只提交 staged 内容
5. 如果没有已暂存内容且用户也未指定路径，停止并要求用户先暂存或指定路径

## 提交信息格式

```text
<emoji> 中文概述

- 变更点 1
- 变更点 2
- 变更点 3

🤖 Generated with <AI_TOOL>

Co-Authored-By: <GIT_USER_NAME> <<GIT_USER_EMAIL>>
```

## 自动识别

创建 commit 前，先识别：
1. Git 身份：运行 `git config --get user.name` 和 `git config --get user.email`
2. AI 工具：
   - Codex 会话使用 `Codex`
   - Claude Code 会话使用 `Claude`

用实际检测值替换 `<GIT_USER_NAME>`、`<GIT_USER_EMAIL>` 和 `<AI_TOOL>`。

## Emoji 选择规则

- 每个 commit 只使用一个 emoji，以主要意图为准
- 当一次提交包含多类改动时，选择最重要的那一类
- 全新功能优先使用 `✨`，已有逻辑调整优先使用 `🔧`，修复破坏性行为优先使用 `🐛`

## 示例

### 只提交已暂存内容

如果已存在 staged 文件，只检查 `git diff --cached`，并且仅基于 staged 内容生成中文提交信息。

### 只提交明确路径

如果用户说 `commit utilities/parser/base_parser.py`，则只检查并暂存该文件，只根据该文件的 diff 生成中文提交信息。

### 不默认扫描全部改动

如果用户只说 `git-commit-zh`，但没有给路径且没有已暂存内容，不要默认扫描整个工作区；应要求用户先暂存，或明确给出提交路径。
