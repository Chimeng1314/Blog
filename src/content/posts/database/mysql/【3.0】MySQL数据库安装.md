# 【二】MySQL数据库介绍
+ MySQL是一个开源免费的关系型数据库管理系统，由瑞典MySQL AB 公司开发，目前属于 Oracle 旗下公司。
+ MySQL 最流行的关系型数据库管理系统，在 WEB 应用方面MySQL是最好的 RDBMS (Relational Database Management System，关系数据库管理系统) 应用软件之一，
+ 具有成本低、速度快、体积小且开放源代码等优点。

## 【4】初始化准备工作
### （1）创建data目录
+ 主要用于存放mysql数据库以及数据的。

注意：是mysql的安装目录！！！！

![](https://oss.silentdream.top/2026/09/27/12-01-18-328ce9d7-image-20240116163932453-ad5dcd.png)

### （2）创建配置文件
+ mysql在windows下的配置文件，叫 my.ini，默认是没有的，我们需要手动创建。
+ 配置文件内容如下
    - 注意：**basedir和datadir的路径要根据自己的路径如实填写**

```plain
[mysqld]
# 设置3306端口
port=3306
# 设置mysql的安装目录
basedir="C:\WinApps\MySQL"
# 设置mysql数据库的数据的存放目录，就是前面手动创建的data目录
datadir="C:\WinApps\MySQL\data"
# 允许最大连接数
max_connections=200
# 允许连接失败的次数。
max_connect_errors=10
# 服务端使用的字符集默认为utf8mb4
character-set-server=utf8mb4
# 创建新表时将使用的默认存储引擎
default-storage-engine=INNODB
# 默认使用“mysql_native_password”插件认证, mysql_native_password
default_authentication_plugin=mysql_native_password
[mysql]
# 设置mysql网络通信的默认字符集
default-character-set=utf8mb4
[client]
# 设置mysql客户端连接服务端时默认使用的端口
port=3306
# 设置mysql客户端的默认字符集
default-character-set=utf8mb4
```

### （2）配置环境变量
+ 打开配置文件

```shell
open -e .bash_profile
```

+ 添加下面的配置内容

```plain
export PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

export PATH=${PATH}:/usr/local/mysql/bin
```

+ 打开配置文件

```shell
open -e ~/.zshrc
```

+ 追加下述配置

```plain
# MySQL environment variables
export MYSQL_HOME=/usr/local/mysql
export PATH=$MYSQL_HOME/bin:$PATH
export PATH=$MYSQL_HOME/usr/libexec:$PATH
export LD_LIBRARY_PATH=$MYSQL_HOME/lib:$LD_LIBRARY_PATH
```

## 【5】配置mysql配置文件
+ **无论是homebrew等方式，在Mac下都是不会生成my.cnf文件，因为已经使用了最优默认值**
+ **如果需要也可以自行新建或配置/etc/my.cnf**

### （1）查看my.cnf的加载顺序
```shell
mysql --verbose --help | grep my.cnf
```

![](https://oss.silentdream.top/2026/09/27/12-01-18-3e9ed77a-image-20240117160802048-75c4a4.png)

+ 默认安装位置 /usr/local/mysql

### （2）示例文件
+ 一般情况下/usr/local/mysql/support-files/下不会有示例文件，如果有可以执行以下命令

```shell
cd /usr/local/mysql/support-files/
sudo cp my-huge.cnf /etc/my.cnf
```

+ 如果没有，也可以手动创建my.cnf文件

```shell
sudo vim /etc/my.cnf
```

# 【补充】<font style="color:rgb(79, 79, 79);">删除 Windows 中的「服务」</font>
## 【一】Windows 中的「服务」可以分为两大类
### 【1】Windows 服务 
+ 在大多数情况下，尝试删除「Windows 服务」并不是一个好主意。 
+ 其中许多服务执行了 Windows 系统的基本功能，删除它们可能会使计算机崩溃。

### 【2】第三方服务 
+ 是由安装的应用程序创建的。大多数应用程序创建的「服务」主要是提供一些后台功能，但我们也可以删除一些不常用的第三方服务，以释放系统性能。

### 【3】小结
+ 其实，一些 Windows 服务也属于「可有可无」的范围，可以在不影响核心系统功能的情况下停止和删除。
+ 但我们强烈建议，不要去删除 Windows 默认的服务。

## 【二】方法 1：使用「注册表」删除 Windows 服务
### 【1】什么是注册表
+ 注册表是 Windows 操作系统和应用程序存储其低层级配置的数据库，当然也包括了「服务」。
+ 在 Windows 中删除任何「服务」最简单方法就是使用「注册表编辑器」：

### 【2】终端打开注册表
+ 使用 **Windows + R **快捷键打开「运行」
+ 执行 **regedit **打开「注册表编辑器」

### 【3】导航到注册表
```properties
计算机\HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services
```

###  【4】选择服务进行删除
+ Windows 上的所有「服务」都由Services目录中的键表示
+ 只需右击要删除的服务名称，然后选择删除即可。

### 【5】小结
+ 下次重新启动 PC 时，该「服务」将会被直接删除。

## 【三】方法 2：使用「命令提示符」删除 Windows 服务
### 【1】引言
+ 「命令提示符」提供了另一种删除「服务」的简单方法
+ 但前提是需要知道想要删除的「服务名称」
+ 所以需要先查看服务名称

### 【2】打开终端
+ 在「开始」菜单中搜索 cmd
+ 以管理员身份打开「命令提示符」

### 【3】查看所有服务
+ 执行以下命令列出当前 Windows 系统中的所有服务和名称：

```shell
sc queryex type=service state=all
```

### 【4】删除服务
+ 可以执行以下命令删除任何不需要的服务：

```shell
sc delete 服务名称
```

### 【5】提示
+ 命令执行成功后会有反馈输出进行提示。

### 【6】小结
+ 命令执行成功后「服务」会被立即删除，不用重启计算机。

## 【四】方法 3：使用「Windows PoserShell」删除 Windows 服务
### 【1】引言
+ 对于许多用户来说，PowerShell 命令比「命令提示符」更有用、更方便。 
+ PowerShell cmdlet 可无限重复使用，允许系统管理员通过运行单个脚本来执行日常任务。

### 【2】打开Powershell
+ 在「开始」菜单中搜索powershell
+ 以管理员身份打开「Windows PowerShell」

### 【3】查看所有服务
+ PowerShell 也可以显示 Windows 系统中所有「服务」的名称
+ 只需使用以下命令即可查看服务列表：

```shell
Get-Service
```

### 【4】删除服务
+ 可以执行以下命令删除任何不需要的服务：

```shell
sc delete 服务名称
```

### 【5】提示
+ 命令执行成功后除报错外不会有成功提示。

### 【6】小结
+ 下次重新启动 PC 时，该「服务」将会被直接删除。

## 【五】方法 4：使用 Autoruns 删除 Windows 服务
### 【1】引言
+ 如果你觉得「注册表」和命令行的操作方式太过复杂或麻烦
+ 可以尝试使用 sysinternals 工具集里面的图形化小工具 Autoruns 来删除 Windows 服务

### 【2】下载autoruns
+ 先去到 autoruns 工具的官网下载它
+ 右击选择「以管理员身份运行」打开它

### 【3】查看服务
+ 切换到「Services」选项卡，可以查看在当前 Windows 中注册的所有「服务」。
+ Autoruns 还会标识「服务」的发布者是否经过验证，帮助你轻松剔除无良第三方服务。

### 【4】删除服务
+ 右键单击要删除的任何「服务」
+ 然后从出现的下拉菜单中选择「Delete」即可删除该服务。

### 【5】小结
+ 操作执行成功后「服务」会被立即删除，不用重启计算机。
