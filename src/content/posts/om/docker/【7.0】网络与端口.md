容器里的 `localhost` 指容器自己，不是你的电脑，也不是另一个容器。理解这一点，很多“数据库连不上”的问题就能定位了。Docker 在同一自定义网络中的容器之间提供名称解析；在 Compose 中，服务名通常就是最方便的连接地址。

# 【一】对外发布端口

```bash
docker run -d --name demo -p 127.0.0.1:8080:80 nginx:alpine
docker port demo
curl http://127.0.0.1:8080
docker rm -f demo
```

`-p 127.0.0.1:8080:80`：只在宿主机回环地址监听 8080，将流量转到容器 80。写成 `-p 8080:80` 时通常会绑定所有宿主机地址，可能让局域网或公网访问到该服务。实际可见性还受系统防火墙、云安全组和路由影响。不要把数据库端口无意暴露给公网。

Dockerfile 中的 `EXPOSE 80` 只是声明服务预期端口，不会自动发布到宿主机；还需要 `-p` 或 Compose `ports`。

# 【二】容器互联

```bash
docker network create appnet
docker run -d --name web --network appnet nginx:alpine
docker run --rm --network appnet curlimages/curl:latest \
  http://web:80
docker rm -f web
docker network rm appnet
```

第二个容器访问 `web:80`，不必把 `web` 的端口映射到宿主机。上面的 `curlimages/curl:latest` 只用于临时演示；在可重复的项目中固定标签或摘要。Compose 默认会为项目建一个网络，[第 9 章](/posts/om/docker/90dockercompose/)可直接用服务名连接。

# 【三】三个常见地址

| 从哪里访问 | 地址示例 | 说明 |
| --- | --- | --- |
| 宿主机访问已发布的服务 | `localhost:8080` | 走宿主机映射端口 |
| 同一 Compose 网络的应用访问数据库 | `db:5432` | `db` 是服务名，走容器端口 |
| 容器访问宿主机服务 | `host.docker.internal` | Docker Desktop 通常支持；Linux Engine 需根据环境配置，不能假定始终可用 |

`docker network inspect 网络名` 可查看连接的容器；`docker inspect 容器名` 可查看网络配置。若连接失败，依次确认服务是否运行、是否在同一网络、监听地址是否为容器可访问的地址，以及端口用的是容器端口还是宿主机端口。

# 【四】补充：网络模式与 Redis 互联练习

## 【1】常见网络模式

| 模式 | 主要用途 | 记住什么 |
| --- | --- | --- |
| bridge | 单机应用 | 优先使用自定义 bridge，便于名称解析 |
| host | 使用宿主网络栈 | 网络隔离更少；平台支持与行为不同 |
| none | 不提供常规网络连接 | 仍有容器自身的回环接口 |
| overlay | 多节点通信 | 常见于 Swarm，不是普通单机网络 |

## 【2】案例：不发布端口连接 Redis

```bash
docker network create redis-lab-net
docker run -d --name redis-lab --network redis-lab-net redis:8-alpine
docker run --rm --network redis-lab-net redis:8-alpine redis-cli -h redis-lab ping
docker network inspect redis-lab-net
docker stop redis-lab
docker rm redis-lab
docker network rm redis-lab-net
```

客户端成功连接时应返回 `PONG`；Redis 初次启动尚未就绪时稍后再试。无需 `-p 6379:6379`，因为通信在同一 Docker 网络内完成。不要把容器 IP 写死，重建后 IP 可能变化。

## 【3】容器访问宿主机

Linux Engine 若需要 `host.docker.internal`，可在创建容器时加 `--add-host=host.docker.internal:host-gateway`。这只是名称映射，宿主服务还必须监听容器能到达的地址，并允许相应网络访问；只绑定宿主机 `127.0.0.1` 的服务通常不能通过 Linux bridge 网关直接访问。

Docker 端口发布会影响宿主防火墙规则，不能只凭 ufw/firewalld 的表面配置判断外部是否可达。开放服务前按[官方防火墙说明](https://docs.docker.com/engine/network/packet-filtering-firewalls/)核对，并从允许的访问来源实际验证。
