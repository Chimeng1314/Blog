# 【14.0】命令速查与术语

| 想做什么 | 命令 | 记住什么 |
| --- | --- | --- |
| 看 Engine 是否可用 | `docker version` | 应看到 Client 和 Server |
| 看当前连接目标 | `docker context show` | 排除连接错 Engine |
| 看运行容器 | `docker ps` | `-a` 包括停止的 |
| 看容器日志 | `docker logs -f 名称` | 先从日志排错 |
| 进入容器 | `docker exec -it 名称 sh` | 需要容器在运行，且有 `sh` |
| 下载镜像 | `docker pull 镜像:标签` | 核对仓库和标签 |
| 构建镜像 | `docker build -t 名称:标签 .` | 点号是构建上下文 |
| 看端口映射 | `docker port 名称` | 区分宿主机和容器端口 |
| 看卷 | `docker volume ls` | 卷独立于容器 |
| 看磁盘占用 | `docker system df` | 清理前先看 |
| 启动 Compose 项目 | `docker compose up -d` | 在 `compose.yaml` 所在目录运行 |
| 查看 Compose 最终配置 | `docker compose config` | 输出可能包含秘密 |
| 停止 Compose 项目 | `docker compose down` | 默认不删命名卷 |

# 【一】容易混淆的词

- **Docker Engine**：负责管理镜像、容器、网络和卷的服务端及相关组件。
- **Docker CLI**：你输入 `docker ...` 时使用的客户端，可连接不同 Engine。
- **Docker Desktop**：macOS/Windows 上常见桌面产品，包含运行 Linux 容器所需的环境；与单独安装 Linux Engine 不是同一安装方式。
- **Dockerfile**：构建单个镜像的步骤说明。
- **Compose / `compose.yaml`**：定义一组服务如何一起运行。
- **镜像层与容器可写层**：镜像层可复用；容器新增/修改的数据若未挂载卷或绑定目录，删除容器时通常一起消失。
- **卷与绑定挂载**：卷由 Docker 管理；绑定挂载直接映射宿主机路径。
- **仓库与注册中心**：仓库存镜像版本，注册中心托管一个或多个仓库。日常口语常混用。

如果只能记住一条排障顺序：`docker ps -a` → `docker logs` → `docker inspect` → 检查端口、网络、挂载和资源。清理之前先判断数据是否在卷中，并确认备份。

# 【二】补充命令速查

| 想做什么 | 命令 | 前置条件/影响 |
| --- | --- | --- |
| 只创建容器 | `docker create --name demo alpine:3.22 sleep 300` | 尚未启动 |
| 启动已有容器 | `docker start demo` | 不会拉取新镜像重新创建 |
| 暂停/恢复 | `docker pause demo` / `docker unpause demo` | 暂停仍占用内存 |
| 看文件变化 | `docker diff demo` | 对比镜像与容器可写层 |
| 查看镜像摘要 | `docker image inspect 镜像名 --format '{{json .RepoDigests}}'` | 未推送/拉取的本地镜像可能为空 |
| 保存/加载镜像 | `docker save -o image.tar 镜像名` / `docker load -i image.tar` | 不包含容器卷数据 |
| 看镜像层历史 | `docker image history 镜像名` | 不等于完整源 Dockerfile |
| 看容器进程 | `docker top 容器名` | 不要求镜像中有 ps |
| 看资源快照 | `docker stats --no-stream` | 结合资源上限分析 |
| 看网络成员 | `docker network inspect 网络名` | 核对服务间连通 |
| 启动一次性任务 | `docker compose run --rm 服务名 命令` | 默认不发布服务端口 |
| 应用构建变更 | `docker compose up -d --build` | 可能重建容器 |

# 【三】学习验收

- 能说清 latest、版本标签、镜像摘要和容器 ID 的区别。
- 能区分 EXPOSE 与端口发布，解释容器自己的 localhost。
- 能区分 restart 与应用新配置的 up，理解 depends_on 的启动边界。
- 能证明普通删除容器不删除命名卷，并完成一次备份恢复。
- 能说明测试与生产为什么应使用同一个已验证的镜像摘要。
