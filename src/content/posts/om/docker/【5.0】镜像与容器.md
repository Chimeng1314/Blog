## 【1】镜像名称

- 首先来看下镜像的名称组成：
  - 镜像名称一般分为两部分：**repository:tag**
- 例如mysql:5.7，这里的 mysql 是 repository，5.7 是 tag，合在一起就是镜像名称，代表5.7版本的MySQL镜像
  - 在没有指定tag时，默认是 `latest`，它只是一个标签名，不保证是最新版本，例如 `mysql:latest`

## 【4】案例二:将nginx镜像导出和加载

- 在这个案例中，我们练习保存、导入镜像
  - 需求：利用docker save将nginx镜像导出磁盘，然后在通过docker load加载回来

利用docker xx --help命令查看docker save和docker load的语法

- 输入docker save --help，结果如下

```bash
[root@localhost ~]# docker save --help

Usage:  docker save [OPTIONS] IMAGE [IMAGE...]

Save one or more images to a tar archive (streamed to STDOUT by default)

Aliases:
  docker image save, docker save

Options:
  -o, --output string   Write to a file, instead of STDOUT
```

- 输入docker load --help，结果如下

```bash
[root@localhost ~]## docker load --help

Usage:  docker load [OPTIONS]

Load an image from a tar archive or STDIN

Options:
  -i, --input string   Read from tar archive file, instead of STDIN
  -q, --quiet          Suppress the load output
```

1.使用docker save导出镜像到磁盘，随后使用ls命令可以查看到nginx.tar文件

```bash
[root@localhost ~]# docker save -o nginx.tar nginx:latest
```

2.使用 ls 查看刚导出的 nginx.tar 文件

```bash
[root@localhost ~]# ls
anaconda-ks.cfg  nginx.tar
```

3.使用docker load加载镜像，在此之前，我们使用命令删除本地nginx镜像

```bash
docker rmi nginx:latest ## rmi是remove image的缩写
```

4.随后运行命令，加载本地文件

```bash
docker load -i nginx.tar
```

## 【2】容器的常见状态

- 运行：进程正常运行
- 暂停：进程暂停，CPU不再运行，不释放内存
- 停止：主进程终止，不再使用 CPU，进程占用的内存会释放；容器配置和可写层仍保留

> - 暂停和停止的操作系统的处理方式不同，暂停是操作系统将容器内的进程挂起，进程的内存仍然保留，CPU 不再执行这些进程；使用 `unpause` 后，程序继续运行。
> - `docker stop` 先发送终止信号，等待超时后才强制结束进程，容器所占的内存回收，保存的仅剩容器的文件系统，也就是那些静态的资源
> - docker rm 是将文件系统也彻底删除，也就是将容器彻底删除掉了

## 【3】命令介绍

- `docker run`：创建并运行一个容器，处于运行状态
- `docker pause`：让一个运行的容器暂停
- `docker unpause`：让一个容器从暂停状态恢复运行
- `docker stop`：停止一个运行的容器
- `docker start`：让一个停止的容器再次运行
- `docker rm`：删除一个容器

## 【4】案例一:创建并运行nginx容器

```bash
docker run --name myNginx -p 127.0.0.1:8080:80 -d nginx:alpine
```

- 命令解读
  - docker run：创建并运行一个容器
  - --name：给容器起一个名字，例如叫做myNginx
  - -p：将宿主机端口与容器端口映射，冒号左侧是宿主机端口，右侧是容器端口
  - -d：后台运行容器
  - nginx：镜像名称，例如nginx
- 这里的-p参数，是将容器端口映射到宿主机端口
- 默认情况下，容器是隔离环境，我们直接访问宿主机的80端口，肯定访问不到容器中的nginx

![img](https://oss.silentdream.top/2026/09/29/17-59-42-f2613434-82827a55ef38c5c66de7f717484647d2-f3bd9b.png)

- 现在，容器的 80 端口和宿主机本地的 8080 端口关联起来，访问 `localhost:8080` 时会转发到容器的 80 端口，这样就能访问nginx了
- 在 Docker 所在机器的浏览器打开 `http://localhost:8080` 即可看到欢迎页；远程机器需按【4.2】使用 SSH 转发

![img](https://oss.silentdream.top/2026/09/29/17-59-41-f6435e68-34bafec2daf04866c18d77a0e651a415-f1572f.png)

- 查看日志记录

```bash
[root@localhost ~]# docker logs myNginx
```

## 【5】案例二

需求：进入Nginx容器，修改HTML文件内容，添加Welcome To My Blog！

提示：进入容器要用到docker exec命令

```bash
[root@localhost ~]## docker exec --help

Usage:  docker exec [OPTIONS] CONTAINER COMMAND [ARG...]

Run a command in a running container

Options:
  -d, --detach               Detached mode: run command in the background
      --detach-keys string   Override the key sequence for detaching a container
  -e, --env list             Set environment variables
      --env-file list        Read in a file of environment variables
  -i, --interactive          Keep STDIN open even if not attached
      --privileged           Give extended privileges to the command
  -t, --tty                  Allocate a pseudo-TTY
  -u, --user string          Username or UID (format: <name|uid>[:<group|gid>])
  -w, --workdir string       Working directory inside the container
```

1.进入容器。进入刚刚我们创建好的nginx容器

```bash
docker exec -it myNginx sh
```

- 命令解读
  - docker exec：进入容器内部，执行一个命令
  - -it：给当前进入的容器创建一个标准输入、输出终端，允许我们与容器交互
  - myNginx：要进入的容器名称
  - sh：在容器内运行 shell；Alpine 变体通常没有 bash

2.进入nginx的HTML所在目录

- 容器内部会模拟一个独立的Linux文件系统，看起来就如同一个linux服务器一样，nginx的环境、配置、运行文件全部都在这个文件系统中，包括我们要修改的html文件
- 查看DockerHub网站中的nginx页面，可以知道nginx的html目录位置在/usr/share/nginx/html
- 我们执行命令进入到该目录

```bash
cd /usr/share/nginx/html
```

查看目录下的文件

```bash
root@10c40cc80352:/usr/share/nginx/html# ls

```

3.修改index.html的内容

- 容器内没有vi命令，无法直接修改，我们使用下面的命令来修改

```bash
sed -i -e 's#Welcome to nginx#Welcome To My Blog#g' index.html
```

# 【四】补充：标签、摘要与分层

## 【1】完整镜像名称

- 完整引用可以写为 `registry/namespace/repository:tag`。
- 例如 `docker.io/library/nginx:alpine`：`docker.io` 是注册中心，`library` 是官方镜像命名空间，`nginx` 是仓库名，`alpine` 是标签。
- 标签可以移动，包括具体版本标签；要精确复现构建结果，应记录镜像摘要。摘要只固定内容，不负责后续安全升级。

```bash
docker pull nginx:alpine
docker image inspect nginx:alpine --format '{{json .RepoDigests}}'
docker image inspect nginx:alpine --format '{{.Os}}/{{.Architecture}}'
docker image history nginx:alpine
```

第一条需要网络；后面查看已拉取镜像。摘要引用形如 `nginx@sha256:...`，省略号是占位说明，实际使用时替换为 inspect 返回的完整摘要。

## 【2】可写层在哪里

- 镜像的只读层可以共享，每个容器通常有自己的可写层。
- 暂停或停止容器不会删除可写层，删除容器会删除它；命名卷不随普通 `docker rm` 自动删除。
- 进入容器修改网页适合练习，正式发布应修改源码并重新构建镜像，或明确使用绑定挂载。`docker commit` 不会自动记录可复现的构建步骤，也不会把挂载卷内容保存进镜像。

## 【3】案例三：观察容器生命周期

需求：区分 `create`、`start`、`stop` 和 `rm`，并观察文件变化。

```bash
docker create --name lifecycle-demo alpine:3.22 sleep 300
docker start lifecycle-demo
docker exec lifecycle-demo sh -c 'echo hello > /tmp/demo.txt'
docker diff lifecycle-demo
docker stop lifecycle-demo
docker ps -a --filter name=lifecycle-demo
docker start lifecycle-demo
docker exec lifecycle-demo cat /tmp/demo.txt
docker stop lifecycle-demo
docker rm lifecycle-demo
```

- `create` 只创建；`run` 组合了创建与启动；`start` 重新启动已有容器，不创建新的可写层。
- 再次启动后能读到 `hello`。删除后，可写层里的文件才随之消失，基础镜像仍保留。
- `docker exec` 运行第二个进程，不会替换容器主进程。退出 exec 打开的 shell 通常不会停止 Nginx；若 shell 本身就是容器主进程，退出后容器会停止。

## 【4】复制文件与镜像归档的区别

```bash
docker cp myNginx:/usr/share/nginx/html/index.html ./nginx-index.html
```

上面需要已有的 `myNginx` 容器；`cp` 复制文件，不是完整备份。`save/load` 保存和加载镜像及其层、标签；`export/import` 处理容器文件系统归档，不能等同于保留完整镜像配置，也不包含挂载卷的数据。
