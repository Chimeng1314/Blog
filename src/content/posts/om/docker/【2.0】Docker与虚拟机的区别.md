# 【一】Docker 与虚拟机的区别

Docker 容器与虚拟机都能为应用提供相对独立的运行环境，但实现方式不同。

虚拟机通过虚拟化硬件运行来宾操作系统；

Linux 容器则作为宿主 Linux 内核上的进程运行，依靠内核机制隔离进程、网络和文件系统。

![容器与虚拟机的结构对比](https://oss.silentdream.top/2026/09/29/17-59-30-a62679a7-150f4a1b6db2a3253502abc08e6a2a08-8f3da7.png)

这里说的“宿主 Linux 内核”也可能是 Docker Desktop 创建的 Linux 虚拟机的内核。在 macOS/Windows 上运行 Linux 容器时，底层仍有虚拟化这一层。

# 【二】放在一起比较

| 维度 | Docker 容器 | 虚拟机 |
| --- | --- | --- |
| 运行单位 | 一个或一组受隔离的进程 | 一套来宾操作系统及其应用 |
| 内核 | 与所在 Linux 主机共享内核 | 来宾系统通常拥有自己的内核 |
| 启动与开销 | 通常启动更快、额外开销更小 | 通常需要启动完整操作系统，开销较大 |
| 隔离边界 | 依赖共享内核及容器配置 | 依赖虚拟化边界及来宾系统配置 |
| 适用场景 | 应用打包、部署、弹性运行 | 需要独立内核、不同操作系统或更明确的虚拟机边界 |

不要用“容器一定是 MB、虚拟机一定是 GB”判断：镜像大小取决于应用和基础镜像，虚拟机磁盘也有精简配置；实际性能受存储、网络、负载和平台影响。两者也不是二选一，生产环境经常在虚拟机中运行容器。

# 【三】记住这一点

容器的核心是**共享内核的进程隔离**，虚拟机的核心是**虚拟硬件上的独立操作系统**。
