# 【一】为什么需要 Docker

## 【1】先从部署的麻烦说起

假设一个项目需要 Node.js、Redis、RabbitMQ 和 MySQL。开发机上的版本与服务器不同，或两套应用要求的依赖版本相互冲突，程序就可能出现“我这里能跑，你那里跑不了”的情况。服务越多、部署的机器越多，手工安装和核对环境的成本就越高。

![多个应用及其依赖带来的部署问题](https://oss.silentdream.top/2026/09/29/17-59-29-917ae7bd-13a573a5383d795a4351ea6dfb32ac9f-def46a.png)

微服务进一步放大了这个问题：每个服务可以独立开发和发布，但每个服务也需要明确自己的运行环境、配置和连接方式。Docker 解决的是其中**应用如何打包与运行**的一部分，不负责自动解决服务发现、数据库备份或高可用。

## 【2】Docker 做了什么

可以先把 Docker 想成一套标准化的打包和运行工具：

1. 用**镜像（image）**保存应用、运行时、所需依赖和启动方式。
2. 从镜像创建**容器（container）**，让应用作为受隔离的进程运行。
3. 将镜像交给仓库保存和分发，使开发、测试、部署使用同一份构建结果。

![应用与依赖被打包到镜像中](https://oss.silentdream.top/2026/09/29/17-59-29-c092a2b0-e6259e5a02035e86bf6f1eb522875f19-82e352.png)

例如，应用 A 和应用 B 各自打包所需版本的用户态依赖，就不必要求宿主机同时安装两套互相冲突的依赖。但配置、网络、持久数据仍需在启动容器时妥善安排。

# 【二】它为什么能跨环境运行

Linux 程序通常通过系统库调用内核能力。不同发行版的用户空间文件和包管理方式可能不同，而 Docker 镜像可以带上应用需要的用户态文件。Linux 容器运行时**共享所在 Linux 主机的内核**，并通过 namespaces、cgroups 等内核能力实现隔离和资源控制。

![镜像、容器与宿主机的关系](https://oss.silentdream.top/2026/09/29/17-58-51-90cf31ee-01-%E9%95%9C%E5%83%8F%E4%B8%8E%E5%AE%B9%E5%99%A8-5854c3.svg)

这使同一镜像在兼容的 Linux 环境中更容易复用，但不能理解成“任意镜像都能在任意机器上运行”：CPU 架构、内核功能、设备、权限及运行时配置都可能造成限制。macOS 和 Windows 上的 Docker Desktop 通常通过 Linux 虚拟机运行 Linux 容器，并非直接调用 macOS 或 Windows 内核。

# 【三】小结

- **镜像**解决“交付什么”：把应用和所需的用户态运行环境组织成可分发的构建结果。
- **容器**解决“怎样运行”：从镜像启动进程，并提供文件系统、网络等隔离。
- **仓库**解决“怎样分发”：保存镜像，供其他机器拉取。

Docker 降低环境不一致带来的部署成本，但镜像要适配目标平台，数据与配置也要单独管理。
