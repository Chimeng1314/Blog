这章区分三层配置：Docker Engine 本身、容器启动参数、应用自己的配置。先判断问题属于哪一层，才不会把应用端口问题误改成 Engine 配置。

# 【一】先确认当前连接的是谁

```bash
docker context ls
docker context show
docker info
docker version
```

CLI 可能连接本机 Desktop、远程 Engine 或 rootless Engine。`docker info` 能看到服务端存储驱动、运行时等信息；输出可能含环境细节，发给别人前检查。Linux Engine 的守护进程配置文件通常是 `/etc/docker/daemon.json`，Docker Desktop 应优先通过其设置界面管理；不要随意套用 Linux 上的 `systemctl` 操作。

# 【二】镜像拉取与镜像源

先用 `docker pull nginx:alpine` 验证。拉取慢可能来自 DNS、代理、出口网络、仓库限流或镜像不存在，不是一种问题。企业/学校网络可按官方文档为 Engine 配置 HTTP(S) 代理或经信任的仓库镜像源。镜像源涉及供应链信任；避免照搬来历不明的加速地址。macOS/Windows Desktop 与 Linux Engine 的代理配置入口不同。

# 【三】限制容器资源

```bash
docker run --rm --memory=512m --cpus=1.0 \
  -p 127.0.0.1:8080:80 nginx:alpine
```

内存和 CPU 限制可避免单个容器独占资源，但设置太低会导致 OOM 或明显变慢。`docker stats` 查看实时占用；`docker inspect 容器` 查看限制。Docker Desktop 还有给 Linux 虚拟机的总资源设置，它与单容器限制是两层不同的上限。

# 【四】重启策略和健康检查

```bash
docker run -d --name web --restart unless-stopped \
  -p 127.0.0.1:8080:80 nginx:alpine
```

`unless-stopped` 适合希望 Engine 重启后恢复的长期服务；交互式一次性任务通常不需要。重启策略只处理退出后的重启，不保证应用真的能响应请求。健康检查需要镜像或 Compose 中定义合适的检查命令；健康检查失败也不等于 Docker 会自动重启一个仍在运行的容器，具体取决于外部编排与监控。

# 【五】日志占用磁盘

应用最好写 stdout/stderr。Linux Engine 可按[日志驱动文档](https://docs.docker.com/engine/logging/configure/)配置日志轮转；例如 `json-file` 的 `max-size`、`max-file`，或考虑 `local` 驱动。先查 `docker info` 当前日志驱动，再结合已有容器和平台要求改配置。更改守护进程默认值通常只对新建容器生效，旧容器需要重建才会采用新配置。不要直接删除 Docker 管理的数据目录来“清日志”。

# 【六】补充：把运行配置写清楚

## 【1】环境变量与启动命令

```bash
docker run --rm --env APP_MODE=development alpine:3.22 printenv APP_MODE
```

预期输出 `development`。`--env-file 文件路径` 可以读取变量文件，但不会替你加密密码。对于定义 CMD 的镜像，镜像名后面的参数通常覆盖 CMD；定义 ENTRYPOINT 时，则通常作为它的参数，见[Dockerfile 篇](/posts/om/docker/80dockerfile与构建/)。

## 【2】重启策略对照

| 策略 | 什么时候重启 | 注意点 |
| --- | --- | --- |
| no | 不自动重启 | 一次性任务常用 |
| on-failure[:次数] | 主进程非零退出 | 不因单纯 unhealthy 而触发 |
| unless-stopped | 尝试恢复未被手动停止的服务 | 手动停止后不会在 Engine 重启时恢复 |
| always | 尝试保持运行 | 手动停止后，Engine 重启时会再次启动 |

`--rm` 与自动重启策略不能组合使用。持续重启通常说明主进程或配置有问题，先查日志，不要只修改重试次数。

## 【3】案例：为日志设置轮转

```bash
docker run -d --name log-demo \
  --log-driver json-file \
  --log-opt max-size=10m \
  --log-opt max-file=3 \
  -p 127.0.0.1:8083:80 nginx:alpine
docker inspect log-demo --format '{{json .HostConfig.LogConfig}}'
```

访问 `http://localhost:8083` 后查看 `docker logs log-demo`；上面为该容器设置轮转，不会修改其他容器的日志策略。结束后正常停止并删除 `log-demo`。

## 【4】健康状态与进程状态

- 健康检查命令必须在镜像内真实存在；不要假定 slim 镜像有 curl。
- 设置检查超时与启动宽限期，避免启动较慢被误判。
- `docker inspect 容器名 --format '{{json .State.Health}}'` 查看探测记录；没有配置健康检查时不会得到健康结果。
- Docker Desktop 总资源、单个容器内存上限和 tmpfs 上限是不同限制；使用 `docker stats --no-stream` 结合实际负载检查。
