遇到问题时，先看容器状态和日志，再检查网络、挂载与资源。不要一上来执行 `docker system prune -a --volumes`；它可能清掉仍要保留的资源。

# 【一】容器启动后立刻退出

```bash
docker ps -a
docker logs --tail 200 容器名
docker inspect 容器名 --format '{{.State.ExitCode}} {{.State.Error}}'
```

常见原因：主进程执行完毕、命令路径错误、缺少环境变量、挂载目录权限不够、端口占用或内存不足。退出码 137 **可能**与 OOM 或被强制终止有关，继续看 `docker inspect` 的 `.State.OOMKilled`、系统日志及资源限制，不能仅凭退出码下结论。

# 【二】网页打不开

1. `docker ps` 看容器是否仍运行，`docker logs` 看服务有无启动。
2. `docker port 容器名` 看宿主机端口；`curl http://127.0.0.1:宿主机端口` 从本机试。
3. 确认应用在容器里监听 `0.0.0.0`，而不是只监听容器自己的 `127.0.0.1`。
4. 从外部访问时，再检查宿主机绑定地址、防火墙、云安全组以及反向代理。

`-p 8080:80` 的前者是宿主机端口，后者是容器端口；容器间访问通常直接用服务名加容器端口。

# 【三】“磁盘满了”与清理

```bash
docker system df
docker image ls
docker container ls -a
docker volume ls
docker builder prune      # 先看将要清理的构建缓存，交互确认
docker image prune        # 清理悬空镜像，交互确认
docker container prune    # 清理已停止容器，交互确认
```

在共享机器上清理前先确认别人是否还需要这些对象。**`docker volume prune` 和 `docker compose down -v` 都可能删除仍有价值的数据**；卷在 Docker 眼里“未使用”，不代表业务不需要。Docker Desktop 的磁盘映像还涉及虚拟机空间回收，按其官方说明操作，不直接删内部文件。

# 【四】Compose 配置不符合预期

```bash
docker compose config
docker compose ps
docker compose logs --tail 100
```

先看最终展开的服务名、端口、挂载源路径和环境变量。注意 `config` 会显示展开的敏感值，不要把完整输出贴到公开渠道。若是代码改了却没生效，确认有无绑定挂载覆盖镜像文件、是否忘了 `docker compose up -d --build`、浏览器是否缓存旧内容。

# 【五】拉取失败

区分镜像名/标签不存在、仓库认证失败、DNS 失败、网络超时和限流。`docker info`、`docker context show` 确认当前 Engine；`docker login` 只解决认证，不解决 DNS。镜像源应选择可信来源，避免复制不明配置到生产服务器。

# 【六】补充：按层排查，不先清空环境

## 【1】状态与事件

```bash
docker inspect 容器名 --format 'status={{.State.Status}} exit={{.State.ExitCode}} oom={{.State.OOMKilled}} error={{.State.Error}}'
docker stats --no-stream
docker events --since 10m
```

替换容器名后执行。`events` 会继续输出后续事件，按 `Ctrl+C` 结束。`OOMKilled=true` 是判断内存问题的重要线索，但还要结合宿主日志、容器限制和其他被杀进程。

## 【2】高频错误对照

| 现象 | 优先检查 | 不要直接做什么 |
| --- | --- | --- |
| bind: address already in use | 已占用的宿主端口与发布配置 | 不要随意终止未知进程 |
| 容器名称冲突 | `docker ps -a --filter name=名称` | 不要强删仍有数据的旧容器 |
| exec format error | 镜像架构、入口文件格式与解释器 | 不要盲目反复重启 |
| Permission denied | 容器用户 UID/GID、挂载权限、SELinux | 不要默认 chmod 777 |
| healthcheck 命令不存在 | 镜像是否包含探测工具 | 不要误认为应用已崩溃 |
| 构建像是旧代码 | 上下文、.dockerignore、缓存和运行镜像 | 不要把 --no-cache 当永久方案 |

## 【3】Compose 环境与服务互联

```bash
docker compose config --environment
docker compose images
docker network inspect 网络名
```

第一条可能输出敏感变量，分享前脱敏。代码已重建但页面仍旧时，检查运行镜像、绑定挂载是否覆盖文件，以及浏览器缓存。容器之间连接失败，核对同一网络、服务名、容器端口和服务监听地址，不用容器 IP 猜测。
