# 【一】TFTP服务搭建

## 【1】TFTP介绍

TFTP（Trivial File Transfer Protocol）是一种网络协议，主要用于文件的传输。在嵌入式交叉开发环境中被广泛使用。

## 【2】查看服务(软件)是否安装

```bash
sudo apt policy tftp tftpd-hpa xinetd
```

## 【3】安装tftp 服务器和客户端

tftp :下载文件的客户端

tftpd-hpa：支持 `-s` 参数的 TFTP 服务器；本例交由 xinetd 启动

xinetd :系统后台服务

```bash
sudo apt install tftp tftpd-hpa xinetd -y
```

## 【4】查看服务是否启动

查看后台服务器是否启动

```bash
sudo systemctl status  xinetd
```

## 【5】设置下载和目录

这个文件是， 配置tftp下载的目录信息  `/etc/xinetd.d/tftp`

```bash
sudo vi /etc/xinetd.d/tftp
```

写入以下配置：

```text
service tftp
{
socket_type        = dgram
protocol           = udp
wait               = yes
user               = root
server             = /usr/sbin/in.tftpd
server_args        = -s /var/tftpboot
disable            = no
per_source         = 11
cps                = 100 2
flags              = IPv4
}
```

```bash
# server_args设置的/var/tftpboot目录是tftp服务器的目录，TFTP客户端就是从这个目录里获取文件的。
# 创建只读下载目录，放入的文件应允许读取（如 0644）。
sudo install -d -o root -g root -m 0755 /var/tftpboot
# 避免 tftpd-hpa 自带服务与 xinetd 同时占用 UDP 69 端口。
sudo systemctl disable --now tftpd-hpa
```

# 【二】nfs服务搭建

## 【1】NFS简介

NFS（Network File system）主要实现了Linux系统之间的资源共享。

它是将某台Linux主机的若干目录共享出来，交由其他Linux主机直接使用。

## 【2】安装NFS服务器

```bash
sudo apt install nfs-kernel-server
```

## 【3】配置NFS服务器

先创建服务端共享目录，假设系统中已有 `linux` 用户及同名组：

```bash
sudo install -d -o linux -g linux -m 0750 /home/linux/work
```

NFS 的普通读写权限依赖客户端与服务端的 UID/GID 映射；即使导出允许 rw，目录权限也必须允许该用户读写。配置 `/etc/exports`：

```bash
sudo vi /etc/exports
```

写入以下示例（按实际网段修改）：

```text
# /etc/exports: the access control list for filesystems which may be exported
#       to NFS clients.  See exports(5).
#
# Example for NFSv2 and NFSv3:
# /srv/homes       hostname1(rw,sync) hostname2(ro,sync)
#
# Example for NFSv4:
# /srv/nfs4        gss/krb5i(rw,sync,fsid=0,crossmnt)
#/srv/nfs4/homes  gss/krb5i(rw,sync)
/home/linux/work  192.168.1.0/24(rw,sync,root_squash,no_subtree_check)
```

## 【4】重启服务器

```bash
sudo systemctl  restart nfs-kernel-server.service
```

## 【5】挂载服务器目录

客户端先安装工具并创建挂载点，服务端地址按实际网络修改：

```bash
sudo apt install nfs-common
sudo mkdir -p /mnt/nfs
sudo mount -t nfs 192.168.1.2:/home/linux/work /mnt/nfs
findmnt /mnt/nfs
```

跨主机挂载时，客户端必须属于 exports 允许的网段。服务端先确认 `/home/linux/work` 存在且目标用户有权限；网段、用户名和目录均需按实际环境调整。不要用 `*` 向所有客户端开放写入，也不要无条件取消 root 映射。

## 【6】取消挂载

```text
sudo umount /mnt/nfs
```

## 【6】永久设置

以上设置仅暂时有效，重启之后又找不到共享文件夹了。使用以下方法设置
在/etc/fstab 文件编辑末尾添加

```text
.host:/ /mnt/hgfs fuse.vmhgfs-fuse allow_other,uid=0,gid=0,umask=022 0 0
```

先用 `sudo mount -a` 与 `findmnt /mnt/hgfs` 验证，再重启。示例按 root 归属挂载；若需普通用户写入，先用 `id` 获取 UID/GID，再把下面配置中的 `uid=0,gid=0` 替换为实际值。设置依赖于宿主机继续启用共享目录。

# 【四】Samba服务搭建

## 【1】Samba简介

Samba是在Linux和UNIX系统上实现SMB协议的一个免费软件，由服务器及客户端程序构成。SMB（Server Message Block，服务器消息块）是一种在局域网上共享文件和打印机的一种通信协议，它为局域网内的不同计算机之间提供文件及打印机等资源的共享服务。

## 【2】检查samba服务是否安装

```bash

```

## 【3】安装samba软件

```bash
sudo apt install samba
```

## 【4】查看samba服务是否启动

```bash
sudo systemctl status smbd.service
```

## 【5】配置共享目录

先确认 `linux` 是本机账户，再创建共享目录：

```bash
sudo install -d -o linux -g linux -m 0770 /home/linux/work
```

```bash
sudo vi /etc/samba/smb.conf
```

执行结果:

在文件末尾添加如下内容。

```ini
# 表示共享目录的名称 , 只是一个标号
[work]
# 表述信息
comment = work folder
# 可浏览
browseable = yes
#共享的路径
path = /home/linux/work
# 新建文件和目录的权限上限
create mask = 0660
directory mask = 0770
#有效的用户 linux
valid users = linux
# 指定linux
force user = linux
# 指定linux
force group = linux
# 禁止匿名访客，使用上面指定的用户认证
public = no
# 可写
writeable = yes
# 有效
available = yes
```

## 【6】设置访问密码


根据提示输入用户密码(登陆Samba共享目录的时候需要密码

# 【五】SSH服务搭建

## 【1】什么是SSH

SSH 为 Secure Shell 的缩写，由 IETF 的网络小组（Network Working Group）所制定；SSH 为建立在应用层基础上的安全协议。SSH 是较可靠，专为远程登录会话和其他网络服务提供安全性的协议。

利用 SSH 协议可以有效防止远程管理过程中的信息泄露问题。SSH最初是UNIX系统上的一个程序，后来又迅速扩展到其他操作平台。SSH在正确使用时可弥补网络中的漏洞。

SSH客户端适用于多种平台。几乎所有UNIX平台—包括HP-UX、Linux、AIX、Solaris、Digital UNIX、Irix，以及其他平台，都可运行SSH。

## 【2】重新获取git的ssh地址

已有克隆无需删除。在仓库目录执行以下命令，把示例组织和仓库名替换为自己的 SSH 地址：

```bash
git remote -v
git remote set-url origin git@gitee.com:your-org/your-repo.git
git remote -v
ssh -T git@gitee.com
```

首次连接先核对平台公布的主机指纹。若尚未克隆仓库，则用页面提供的 SSH 地址执行 `git clone`。

# 【补充】验证与故障排查

TFTP 无认证和加密，仅在可信实验网络中使用；下载前把测试文件放入服务根目录，用 `ss -lun` 查看 UDP 69 是否监听。NFS 在服务端用 `sudo exportfs -ra`、`sudo exportfs -v` 检查导出，客户端用 `findmnt /mnt/nfs` 验证。Samba 用 `testparm -s` 检查配置，并确认共享目录存在、账户与目录权限一致。SSH 先用 `ssh -v 用户名@地址` 定位连接或认证错误，Ubuntu 服务端查看 `journalctl -u ssh -b`；主机指纹变化必须核实原因后处理。Git 用 `git status` 和 `git remote -v` 区分本地状态与远程地址，推送后再到平台确认提交。
