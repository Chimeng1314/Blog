# 【一】rpm与deb的软件包理解

最初，基于Linux系统的开发者在完成应用程序开发后，将很多二进制文件发给用户，用户使用之前需要将很多程序逐个安装。

Debian 系发行版使用 `.deb` 软件包格式，将程序文件、元数据和维护脚本等内容打包。软件包管理器负责安装、卸载、查询与升级；配置文件和依赖关系则需要结合具体工具和策略处理。

RPM 是 Red Hat 等发行版使用的软件包格式与底层管理工具。`.deb` 与 `.rpm` 不可直接互换，应使用与当前发行版匹配的软件源和包格式。

随着Linux操作系统规模的不断扩大，系统中软件包间复杂的依赖关系，导致Linux用户麻烦不断。

Debian Linux开发出了APT软件包管理器。

检查和修复软件包依赖关系

利用Internet网络帮助用户主动获取软件包

APT工具再次促进了Deb软件包更为广泛地使用，成为Debian Linux的一个无法替代的亮点。

# 【二】`dpkg`命令行管理工具

## 【1】离线软件包安装工具

dpkg是最早的Deb包管理工具，它在Debian一提出包管理模式后就诞生了。使用`dpkg`可以实现软件包的安装、编译、卸载、查询，以及
应用程序打包等功能。但是由于当时Linux系统规模和Internet网络条件的限制，没有考虑到操作系统中软件包存在如此复杂的依赖关系，
以及帮助用户获取软件包（获取存在依赖关系的软件包）。

因而，为了解决软件包依赖性问题和获取问题，就出现了APT工具。

`dpkg` 是 Debian/Ubuntu 的底层软件包管理工具，用于安装、卸载和查询 `.deb` 包。它不负责从软件源下载软件包，也不会自动选择并安装所需依赖；日常优先使用 `apt`。

## 【2】缺陷

第一，不能主动从镜像站点获取软件包；

第二，安装本地包时不会自动下载和解析依赖；依赖不满足时 `dpkg` 可能报错并留下未配置的软件包。

因此，在对一个软件组件的依赖关系不清楚的情况下，建议使用APT软件包管理器。除非用户对软件包的依赖关系非常清楚，再使用dpkg

## 【3】`dpkg`相关命令

```bash
dpkg -i <package>    # install 安装一个在本地文件系统上存在的Debian软件包
dpkg -r <package>    # remove  移除一个已经安装的软件包
dpkg -P <package>    # purge   移除已安装软件包及配置文件
dpkg -L <package>    # 列出某个已安装软件包安装的文件
dpkg -s <package>    # status  显出软件包的安装状态
dpkg -l [pattern]    # 列出软件包及状态
dpkg -S <path>       # 查询某个文件属于哪个已安装软件包
dpkg-deb --info <file.deb>      # 查看本地 .deb 包元数据
dpkg-deb --contents <file.deb>  # 列出本地 .deb 包包含的文件
sudo dpkg-reconfigure <package> # 重新配置一个已安装软件包
```

# 【三】apt命令行管理工具

APT系列工具可能是Deb软件包管理工具中功能最强大的。

Ubuntu将所有的开发软件包存放在Internet上的许许多多镜像站点上。用户可以选择其中最适合自己的站点作为软件源。然后，在APT工
具的帮助下，就可以完成所有的软件包的管理工作，包括维护系统中的软件包数据库、自动检查软件包依赖关系、安装和升级软件包、从
软件源镜像站点主动获取相关软件包等。

常用的 APT 前端是 `apt`。它适合交互式使用；脚本中通常使用输出和接口更稳定的 `apt-get`、`apt-cache`。

## 【1】apt install  安装软件

```bash
sudo apt install <软件名称>
sudo apt -f install   # 尝试修复中断安装或未满足依赖造成的状态
#例如
sudo apt install sl   # 小火车；安装后使用小写的 sl 执行
sudo apt install snake4 # 贪吃蛇游戏 , 可以使用snake4 启动程序
```

## 【2】apt remove 卸载软件

```bash
sudo apt remove  <软件名称>
sudo apt autoremove  #  自动卸载系统不再需要的软件包
# 例如
sudo apt remove sl   # 卸载火车软件
sudo apt remove snake4   # 卸载贪吃蛇游戏
```

## 【3】apt policy 查看软件安装状态

```bash
apt policy <软件名称>
apt policy gcc     # 检查 gcc 的安装状态
apt policy sl      # 检查 sl 的可用版本与安装状态
apt policy snake4  # 检查 snake4 的可用版本与安装状态
```

## 【5】apt purge 卸载软件和配置文件

```bash
sudo apt purge  <软件名称>
sudo apt purge snake4  # 卸载软件和清除配置文件
例如:
linux@ubuntu:~$ sudo apt purge snake4
```

## 【6】apt search 搜索软件包

在可用软件包的名称和描述中搜索关键字。搜索的是软件包索引，不一定表示该包已安装。

```bash
apt search <软件包名称>
# 例如
sudo apt search snake4
```

## 【7】apt update 更新软件目录

从已配置的软件源下载最新的软件包索引；它不安装或升级软件包。安装、升级前应先确认软件源可信且与当前发行版版本匹配。

```bash
sudo apt update    # 更新软件源索引
sudo apt list --upgradable   # 查看可升级的软件信息
例如：
linux@ubuntu:~$ sudo apt update
```

## 【8】apt upgrade 更新软件到最新

在不删除已安装软件包的前提下升级可安全升级的软件包；若涉及依赖替换或删除，可能需要 `sudo apt full-upgrade`，执行前必须核对变更列表。

```bash
sudo apt upgrade
```

例如

```bash
linux@ubuntu:~/work$ sudo apt upgrade
```

## 【9】apt clean 删除下载的软件包

在安装软件时 ， 需要先下载软件包到本地， 之后才可以安装软件包

软件包被下载在：` /var/cache/apt/archives/`

```bash
sudo apt autoclean   # 清除老版本的软件包 ， 保留新版本的软件包
sudo apt clean       # 把所有下载的软件包删除掉
```

# 【补充】验证与故障排查

安装后用 `apt policy 包名` 和 `dpkg -s 包名` 确认版本与状态。依赖中断时先读报错，再用 `sudo dpkg --configure -a` 或 `sudo apt --fix-broken install` 修复；遇到锁占用先等待或排查正在运行的包管理进程，不要直接删除锁文件。
