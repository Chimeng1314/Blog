# 【一】环境变量的概念

## 【1】环境变量的含义

环境变量是由 Shell 或进程维护的一组“名称=值”数据。子进程会继承父进程中已导出的环境变量，因此命令和应用程序可据此获取语言、路径、家目录等运行信息；并非所有运行环境都由环境变量决定。

## 【2】环境变量的分类

按生效的范围分类。

系统环境变量：公共的，对全部的用户都生效。

用户环境变量：用户私有的、自定义的个性化设置，只对该用户生效。
按生存周期分类。

永久环境变量：在环境变量脚本文件中配置，用户每次登录时会自动执行这些脚本，相当于永久生效。

临时环境变量：使用时在Shell中临时定义，退出Shell后失效。

## 【3】Linux环境变量

环境变量名通常由字母、数字和下划线组成，且不能以数字开头；名称区分大小写，按惯例常使用大写字母。

例如 PATH、HOSTNAME、LANG 等。

# 【二】常用的环境变量

用`env`命令的时候，满屏显示了很多环境变量，不方便查看，可以用`grep`筛选。
```bash

```

例如查看环境变量名中包含PATH的环境变量。

```bash
env | grep 'PATH'
```


echo命令

```bash

```

```bash
linux@ubuntu:~/work$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
linux@ubuntu:~/work$ echo $LANG

```

注意，符号$不能缺少，这是语法规定。

## 【2】常用的环境变量

### （1）PATH

可执行程序的搜索目录，可执行程序包括Linux系统命令和用户的应用程序，PATH变量的具体用法本文后面的章节中有详细的介绍.

### （2）LANG

Linux系统的语言、地区、字符集，LANG变量的具体用法本文后面的章节中有详细的介绍。

### （3）HOSTNAME

服务器的主机名。

### （4）SHELL

用户的登录 Shell 路径；进入其他 Shell 后，`$SHELL` 不一定改变。查看当前 Shell 进程可运行 `ps -p $$ -o comm=`。

### （5）HISTSIZE

保存历史命令的数目。

### （6）USER

当前登录用户的用户名。

### （7）HOME

当前登录用户的主目录。

### （8）PWD

当前工作目录。

### （9）LD_LIBRARY_PATH

C/C++语言动态链接库文件搜索的目录，它不是Linux缺省的环境变量，但对C/C++程序员来说非常重要，具体用法本文后面的章节中有详细的介绍。

### （10）示例

```bash
linux@ubuntu:~/work$ env | grep PATH
WINDOWPATH=1
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
linux@ubuntu:~/work$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
linux@ubuntu:~/work$ echo $LANG
zh_CN.UTF-8
linux@ubuntu:~/work$ echo $HOSTNAME
ubuntu
linux@ubuntu:~/work$ echo $SHELL
/bin/bash
linux@ubuntu:~/work$ echo $HISTSIZE
1000
linux@ubuntu:~/work$ echo $USER
linux
linux@ubuntu:~/work$ echo $HOME
/home/linux
linux@ubuntu:~/work$ echo $PWD
/home/linux/work
linux@ubuntu:~/work$ echo $LD_LIBRARY_PATH
```

# 【三】设置环境量

```bash
变量名='值'   # 等号之间不能有空格
```

```bash
export 变量名='值'     # export 导出的意思 ,  告诉shell , 有一个变量被定义了
```

如果环境变量的值没有空格等特殊符号，可以不用单引号包含。

示例：

```bash
export ORACLE_HOME=/oracle/home            				 # 值没有特殊的, 不用单引号
export ORACLE_BASE=/oracle/base
export ORACLE_SID=snorcl11g
export NLS_LANG='Simplified Chinese_China.ZHS16GBK'      # 如果值有空格等特殊字符需要使用 单引号包含
export PATH="$PATH:$HOME/bin:$ORACLE_HOME/bin"          # 把更多的 bin 目录加入 PATH
export LD_LIBRARY_PATH="$LD_LIBRARY_PATH:$ORACLE_HOME/lib"
```

不要在 `PATH` 或 `LD_LIBRARY_PATH` 的开头、结尾写空目录（例如末尾的 `:`）。空目录在不少实现中会被解释为当前目录，可能带来误执行风险。修改 `PATH` 时也应保留原有的 `$PATH`，避免系统命令无法找到。

采用export设置的环境变量，在退出Shell后就会失效，下次登录时需要重新设置。

如果希望环境变量永久生效，需要在登录脚本文件中配置。

## 【1】系统环境变量

系统环境变量对全部的用户生效，设置系统环境变量有三种方法。

### （1）`/etc/profile`

在`/etc/profile`文件中设置。

用户登录时执行`/etc/profile`文件中设置系统的环境变量。但是，Linux不建议在`/etc/profile`文件中设置系统环境变量。

### （2）`/etc/profile.d`

在`/etc/profile.d`目录中增加环境变量脚本文件，这是Linux推荐的方法。

在 Debian/Ubuntu 中，登录 Shell 通常会读取 `/etc/profile`，该文件会按配置读取 `/etc/profile.d/` 中的脚本。对于自行创建的脚本，建议使用明确的文件名，例如 `/etc/profile.d/my-env.sh`，并通过包管理或配置管理维护；不要随意删除系统或软件包提供的脚本。

`/etc/profile.d` 目录下可能包含多个脚本，具体内容随系统与安装的软件而变化。例如可用下列命令查看：

```bash
linux@ubuntu:/etc/profile.d$ ls
01-locale-fix.sh  bash_completion.sh     debuginfod.csh  gnome-session_gnomerc.sh  vte-2.91.sh
xdg_dirs_desktop_session.sh  Z99-cloud-locale-test.sh
apps-bin-path.sh  cedilla-portuguese.sh  debuginfod.sh   im-config_wayland.sh      vte.csh      Z99-
cloudinit-warnings.sh
linux@ubuntu:~/work$
```

`bash_completion.sh` 的用途是加载 Bash 补全功能，并不是通用环境变量配置文件。系统脚本内容随发行版与版本变化较大，学习时应以本机文件为准。

### （3）`/etc/bash.bashrc`

在`/etc/bash.bashrc`文件中设置环境变量。

该文件影响交互式 Bash；Debian/Ubuntu 的文件名是 `/etc/bash.bashrc`，其他发行版可能使用 `/etc/bashrc`。它通常不会被非交互式脚本或所有登录场景读取，因此不适合作为“对所有进程全局生效”的唯一配置位置。

```bash
linux@ubuntu:~/work$ vi /etc/bash.bashrc
linux@ubuntu:~/work$ cat /etc/bash.bashrc
# System-wide .bashrc file for interactive bash(1) shells.
# To enable the settings / commands in this file for login shells as well,
# this file has to be sourced in /etc/profile.
# If not running interactively, don't do anything
[ -z "$PS1" ] && return
# check the window size after each command and, if necessary,
# update the values of LINES and COLUMNS.
shopt -s checkwinsize
# set variable identifying the chroot you work in (used in the prompt below)
if [ -z "${debian_chroot:-}" ] && [ -r /etc/debian_chroot ]; then
debian_chroot=$(cat /etc/debian_chroot)
fi
# set a fancy prompt (non-color, overwrite the one in /etc/profile)
# but only if not SUDOing and have SUDO_PS1 set; then assume smart user.
if ! [ -n "${SUDO_USER}" -a -n "${SUDO_PS1}" ]; then
PS1='${debian_chroot:+($debian_chroot)}\u@\h:\w\$ '
fi
# Commented out, don't overwrite xterm -T "title" -n "icontitle" by default.
# If this is an xterm set the title to user@host:dir
#case "$TERM" in
#xterm*|rxvt*)
#    PROMPT_COMMAND='echo -ne "\033]0;${USER}@${HOSTNAME}: ${PWD}\007"'
#    ;;
#*)
#    ;;
#esac
```

### （1）`.profile`（推荐首选）

当用户登录时执行，每个用户都可以使用该文件来配置专属于自己的环境变量。

### （2）`.bashrc`

交互式 Bash 启动时读取。许多 Ubuntu 默认的 `.profile` 会在登录 Shell 中主动读取 `.bashrc`；是否如此应查看本机文件。适合放交互式别名、提示符和工具初始化。需要被图形会话或非交互程序继承的变量，应结合登录方式选择 `.profile`、桌面会话配置或服务的专用配置。

### （3）`.bash_logout`

当每次退出系统（退出bash shell）时执行该文件。

### （4）`.bash_history`

保存了当前用户使用过的历史命令。

# 【四】重要环境变量的详解

## 【1】PATH环境变量

可执行程序的搜索目录，可执行程序包括Linux系统命令和用户的应用程序。

如果可执行程序的目录不在PATH指定的目录中，执行时需要
指定目录。

1）PATH 环境变量存放目录列表，目录之间用冒号 `:` 分隔。只有显式加入 `.` 时才会搜索当前目录；从安全角度看，通常不建议把 `.` 加入 PATH。

```text
export PATH="目录1:目录2:目录3:...:目录n"
```

2）PATH缺省包含了Linux系统命令所在的目录（`/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin`），如果不包含这些目录，Linux的常
用命令也无法执行（要输入绝对路径才能执行）。

示例：

```bash
linux@ubuntu:~$ ls
Desktop  Documents  Downloads  Music  Pictures  Public  snap  Templates  Videos  work
linux@ubuntu:~$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
linux@ubuntu:~$ export PATH=
linux@ubuntu:~$ ls
bash: ls: 没有那个文件或目录
linux@ubuntu:~$ /bin/ls
Desktop  Documents  Downloads  Music  Pictures  Public  snap  Templates  Videos  work
linux@ubuntu:~$
3）在用户的.profile文件中，会对PATH进行扩充，如下：
export PATH=$PATH:$HOME/bin
4）如果PATH变量中没有包含圆点.，执行当前目录下的程序需要加./或使用绝对路径。
linux@ubuntu:~/work$ ls
a.out  hello.c  jeffy-vim-sl-v5.0  jeffy-vim-sl-v6.0.tar.xz
linux@ubuntu:~/work$ a.out
a.out：未找到命令
linux@ubuntu:~/work$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
linux@ubuntu:~/work$ ./a.out
hello world!!
linux@ubuntu:~/work$
```

使用 `./a.out` 明确表示运行当前目录中的程序，避免因 PATH 中同名程序而误执行。

## 【2】LD_LIBRARY_PATH环境变量

C/C++语言动态链接库文件搜索的目录，它不是Linux缺省的环境变量，但对C/C++程序员来说非常重要。

LD_LIBRARY_PATH 环境变量存放的也是目录列表，目录之间用冒号 `:` 分隔。它会影响动态链接器的库查找顺序；不建议将当前目录加入其中，也不建议把它作为系统级长期配置的首选方案。

```text
export LD_LIBRARY_PATH="目录1:目录2:目录3:...:目录n"
```

若需要让系统长期识别某个受信任的共享库目录，通常在 `/etc/ld.so.conf.d/` 新建配置文件并执行 `sudo ldconfig`；开发阶段也可在构建时使用 rpath。应避免为了解决单个程序的问题而全局覆盖 `LD_LIBRARY_PATH`。

#  【五】环境变量的生效

1）在Shell下，用export设置的环境变量对当前Shell立即生效，Shell退出后失效。

2）在脚本文件中设置的环境变量不会立即生效，退出Shell后重新登录时才生效，或者用source命令让它立即生效。
例如：

```text
source /etc/profile
```

# 【补充】验证与故障排查

修改配置后新开终端验证 `printenv 变量名`；只在当前 Shell 有值而子进程读取不到时，检查是否使用 `export`。PATH 被覆盖导致命令失效时用绝对路径启动编辑器恢复配置，并确认修改的是当前 Shell 实际读取的启动文件。
