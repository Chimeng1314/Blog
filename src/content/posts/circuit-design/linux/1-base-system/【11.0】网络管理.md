# 【一】查看网络设置

## 【1】ifconfig 显示与设置网络命令

`ifconfig` 来自传统 net-tools 工具集，用于显示或临时设置网络接口参数。现代 Linux 更推荐使用 iproute2 工具集中的 `ip` 命令；许多 Ubuntu 安装默认不包含 `ifconfig`。

不建议使用 `ifconfig` 作为持久化配置方式，因为重启或网络服务重载后设置通常会丢失。持久配置应交给发行版的网络管理方案（Netplan、NetworkManager、systemd-networkd 等）。

语法格式： ifconfig [参数] [网卡设备]

常用参数：
add<地址>
设置网络设备IPv6的IP地址
del<地址>
删除网络设备IPv6的IP地址
down
关闭指定的网络设备
up
启动指定的网络设备

首先说明下eth0与ens33的关系:

目前的主流网卡为使用以太网络协定所开发出来的以太网卡 （Ethernet），因此我们 Linux 就称呼这种网络接口为 ethN （N 为数字）。

举例来说，主机上面有一张以太网卡，因此主机的网络接口就是 eth0 (第一张为 0 号开始）。

新的 CentOS 7 开始对于网卡的编号有另一套规则，网卡的界面代号与网卡的来源有关,网卡名称会是这样分类的：

eno1 ：代表由主板 BIOS 内置的网卡

ens1 ：代表由主板 BIOS 内置的 PCI-E 界面的网卡

enp2s0 ：代表 PCI-E 界面的独立网卡，可能有多个插孔，因此会有 s0, s1... 的编号～

eth0 ：如果上述的名称都不适用，就回到原本的默认网卡编号

所以会有ens33这种网卡表现形式。

等价的现代常用命令：

```bash
ip -brief address             # 简洁查看接口与地址
ip link show dev ens33        # 查看接口状态
ip address show dev ens33     # 查看指定接口地址
sudo ip link set ens33 up     # 临时启用接口
```

保留 `ifconfig` 示例以便阅读旧资料：

```bash
ifconfig  # 查看系统的网卡信息

ifconfig ens33   #查看具体某一个网卡的信息
```

```bash
sudo ifconfig ens33 192.168.1.200 netmask 255.255.255.0  # 设置ip地址和子网掩码 , 只设置ip地址 , 重启后消失
sudo ifconfig ens33 192.168.1.199  # 只设置ip地址 , 重启后消失
# 在本地控制台练习；关闭当前 SSH 使用的接口会断开连接
sudo ifconfig ens33 down   # 关闭网卡
sudo ifconfig ens33 up  # 启动网卡 , 启动网卡后, 原来ifconfig设置的ip会丢失
```

```bash
linux@ubuntu:~/work$ ifconfig   # ubuntu 默认没有集成ifconfig ,需要额外的安装命令
Command 'ifconfig' not found, but can be installed with:
sudo apt install net-tools

linux@ubuntu:~/work$ sudo apt install net-tools    # 安装ifconfig 命令
```

## 【2】route 显示与设置路由命令

`route` 也是 net-tools 中的旧工具，用于显示与临时设置路由。现代系统推荐 `ip route`；跨网段通信除了本机路由外，还依赖网关、对端回程路由和防火墙策略。

语法格式： route [参数]

常用参数：
-A
设置地址类型（ 默认IPv4）
-C
打印核心的路由缓存
-v
详细信息模式
-n
直接显示数字形式的ip地址
-e
netstat格式显示路由表
-net
到一个网络的路由表
-host
到一个主机的路由表
Add
增加指定的路由记录
Del
删除指定的路由记录
Target
目的网络或目的主机
gw
设置默认网关
mss
设置 TCP 最大段大小相关的路由参数（单位为字节；旧版 route 的 mss 参数语义见本机手册）
window
指定通过路由表的TCP连接的窗口大小
dev
路由记录所表示的网络接口

推荐的现代写法：

```bash
ip route show
sudo ip route add 192.168.10.0/24 dev ens33
sudo ip route del 192.168.10.0/24 dev ens33
```

保留 `route` 示例以便理解旧资料：

```bash

route del -net 192.168.10.0 netmask 255.255.255.0 dev ens33  # 删除一个路由连接
```

## 【4】netstat命令

`netstat` 来自传统 net-tools 工具集，可显示连接、路由和接口统计信息。现代 Linux 推荐使用 `ss` 查看套接字、`ip` 查看接口与路由；系统可能默认未安装 `netstat`。

Windows 也提供 `netstat`，但选项、输出和权限行为与 Linux 并不完全一致，不能直接假定参数相同。

语法格式：netstat [参数]

常用参数：
-a
显示所有连线中的Socket
-p
显示正在使用Socket的程序识别码和程序名称
-l
仅列出在监听的服务状态
-t
显示TCP传输协议的连线状况
-u
显示UDP传输协议的连线状况
-i
显示网络界面信息表单
-r
显示路由表信息
-n
直接使用IP地址，不通过域名服务器

推荐的现代写法：

```bash
ss -lntup                  # 查看监听 TCP/UDP 套接字与进程（进程信息通常需要 sudo）
ss -ant                    # 查看 TCP 套接字
ip -s link                 # 查看接口统计
ip route show              # 查看路由表
sudo ss -lntp '( sport = :22 )'  # 查看 TCP 22 端口监听者
```

保留 `netstat` 示例以便阅读旧资料：
```bash
netstat -a   # 显示系统网络中的所有连接信息
netstat -nu  #显示系统网络状态中的UDP连接信息
netstat -apu #显示系统网络状态中的UDP连接端口号使用信息
netstat -i   #显示网卡当前状态信息
netstat -r   #显示网络路由表状态信息
netstat -ap | grep ssh   #找到某个服务所对应的连接信息
```

# 【二】测试网络连接

## 【1】ping 命令

ping命令的功能是用于测试主机间网络连通性，发送出基于ICMP传输协议的数据包，要求对方主机予以回复，若对方主机的网络功能没有问题且防火墙放行流量，则就会回复该信息，我们也就可得知对方主机系统在线并运行正常了。

不过值得我们注意的是Linux与Windows相比有一定差异，Windows系统下的ping命令会发送出去4个请求后自动结束该命令；而Linux系统则不会自动终止，需要用户手动按下组合键“Ctrl+c”才能结束，或是发起命令时加入-c参数限定发送个数。

语法格式：ping [参数] 目标主机(ip地址或域名)

常用参数：
-d
使用Socket的SO_DEBUG功能
-c
指定发送报文的次数
-i
指定收发信息的间隔时间
-I
使用指定的网络接口送出数据包
-l
设置在送出要求信息之前，先行发出的数据包
-n
只输出数值
-p
设置填满数据包的范本样式
-q
不显示指令执行过程
-R
记录路由过程
-s
设置数据包的大小
-t
设置存活数值TTL的大小
-v
详细显示指令的执行过程

```bash
ping 192.168.1.1        # 可以测试 电脑和路由器之间是否连接可以通信  Ctrl+c结束测试
ping www.baidu.com      # 测试外网的联通
ping -c 4 www.baidu.com # 发送4个数据包
```

## 【2】traceroute命令

traceroute命令用于追踪数据包在网络上的传输时的全部路径，它默认发送的数据包大小是40字节。通过traceroute我们可以知道信息从你的计算机到互联网另一端的主机是走的什么路径。当然每次数据包由某一同样的出发点（source）到达某一同样的目的地(destination)走的路径可能会不一样，但基本上来说大部分时候所走的路由是相同的。

traceroute通过发送小的数据包到目的设备直到其返回，来测量其需要多长时间。一条路径上的每个设备traceroute要测3次。输出结果中包括每次测试的时间(ms)和设备的名称（如有的话）及其ip地址。

语法格式：traceroute [参数] [域名或者IP]

## 【1】图形化配置(network-manager)

Ubuntu 桌面版通常使用 NetworkManager，服务器版常见 systemd-networkd；实际渲染器与安装方式、版本和管理员配置有关。虚拟机与物理机的配置原则相同，但接口名称和网络模式可能不同。

Ubuntu 的许多版本使用 Netplan 管理网络配置，文件位于 `/etc/netplan/*.yaml`。`/etc/network/interfaces` 是否生效取决于是否仍由 ifupdown 管理，不能一概而论；修改前先确认本机正在使用的网络管理器和现有配置。

`/etc/netplan/01-network-manager-all.yaml`

Netplan 是配置前端，会根据 `renderer` 把 YAML 配置生成给 NetworkManager 或 systemd-networkd。若系统另外存在 NetworkManager 原生连接配置，可能与 Netplan 配置共同影响接口；应选择一个明确的管理入口，避免同一接口被重复配置。

## 【2】命令行配置

`/etc/netplan/01-network-manager-all.yaml`

```yaml
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    ens33:                       # 网卡名称，以 `ip -brief address` 的输出为准
      addresses:
        - 192.168.1.20/24         # /24 对应掩码 255.255.255.0
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [223.5.5.5, 1.1.1.1]
```

YAML 的缩进必须一致，通常每层使用 2 个空格，不能混用 Tab。`ens33` 只是示例接口名；请使用 `ip -brief address` 或 `networkctl` 查到的本机名称替换。`gateway4` 在较新的 Netplan 版本中已被标记为过时，上例改用默认路由 `routes` 表示法。

修改远程主机的网络配置前，建议在具备控制台的情况下执行；可先使用 `sudo netplan try` 进行可回滚测试，确认连接正常后再应用。

修改ip和网关信息
